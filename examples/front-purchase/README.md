# Purchase scene - visual study

Lot 1: an original fantasy village, one provisional human merchant and a district deed.
This is a standalone design demo, not the live game. No server API, tokens, real players,
private cards or network service are used. It does not replace the existing playable page.

From the repository root:

```text
python -m http.server 8877 --bind 127.0.0.1 --directory examples/front-purchase
```

Open http://127.0.0.1:8877/ for the player presentation, or add ?mode=stream for the
read-only presentation. Buy and Pass select snapshots generated by the Python engine.
The scene stops at that result: it does not implement auctions or the rest of a game.
Reset scene is a demo control. Mode changes preserve the current scene.
There is no permanent storage. Opening index.html directly also works.

The illustration and merchant SVGs are original provisional artwork. There are no
external fonts, images, scripts, copied assets or new runtime dependencies.
The town's descriptive copy is decorative, not a player message or a game rule.
Current rent means the exact current engine value, including zero on unowned land.

## Fixture maintenance

```text
python examples/front-purchase/generate_fixtures.py
node --test tests/front_purchase.test.cjs
```

The generator constructs a synthetic purchase state and calls apply for buy and pass,
then exports spectator views only. Never put private player views in these files.
No prices, rent rules or economy calculations are implemented in JavaScript.

## Review targets

Review the tone, the provisional merchant, deed hierarchy and readability at 1920x1080
and 1280x720. Check an additional narrow window and keyboard navigation.
This is not an OBS performance test, a completed 40-square board or a playable match.
A later connected front must use the validated server contracts and handle resynchronization.

No additional weekly maintenance job or service is introduced by this study.
